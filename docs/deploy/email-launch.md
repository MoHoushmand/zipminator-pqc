## Day-2 tasks (launch day, not feature work)

### 1. DNS records on `zipminator.zip`

The domain is owned (registered, used for the web app at https://www.zipminator.zip). Add the following records before sending mail:

```
;; A/AAAA for the mail host
mail.zipminator.zip.    A     <PUBLIC_IPv4>
mail.zipminator.zip.    AAAA  <PUBLIC_IPv6>

;; MX
zipminator.zip.         MX    10 mail.zipminator.zip.

;; SPF (allow only our mail host + chosen relay)
zipminator.zip.         TXT   "v=spf1 mx a:mail.zipminator.zip include:_spf.<RELAY>.com -all"

;; DKIM (paste contents of email/mailserver/config/dkim/keys/zipminator.zip/s1.txt)
s1._domainkey.zipminator.zip. TXT  "v=DKIM1; k=rsa; p=<BASE64_PUBKEY>"

;; DMARC (start with quarantine, tighten to reject after 30 days clean)
_dmarc.zipminator.zip.  TXT   "v=DMARC1; p=quarantine; rua=mailto:dmarc-reports@zipminator.zip; ruf=mailto:dmarc-failures@zipminator.zip; fo=1"
```

The DKIM TXT value is generated by the public side of the s1.private key:

```bash
cd email/mailserver/config/dkim/keys/zipminator.zip
openssl rsa -in s1.private -pubout 2>/dev/null \
  | grep -v '^-----' | tr -d '\n'
```

Paste that as the `p=` value, prefixed with `v=DKIM1; k=rsa; `.

### 2. Mail relay decision (pick one)

| Option | Cost | Setup time | Notes |
|---|---|---|---|
| **Self-hosted Postfix** on Hetzner / Linode / Vultr | $5-20/mo | 4-8h | Use the existing `email/mailserver/Dockerfile` (Postfix 3.10 + Dovecot 2.3.21 + PQC TLS). Requires reverse-DNS setup with the host, IP reputation warmup, blocklist monitoring (Spamhaus, Barracuda). Highest privacy, hardest to operate. |
| **AWS SES** | $0.10 / 1000 sent | 1-2h | Configured by setting `SMTP_RELAY_HOST=email-smtp.us-east-1.amazonaws.com:587` in `email/transport/.env`. Cheapest at scale; SES handles reputation. Requires SES domain verification (DKIM via 3 CNAMEs) and out-of-sandbox approval. |
| **Postmark** | $1.25 / 1000 sent (free 100/mo) | 30min | Cleanest deliverability; transactional-only (no bulk). Good for beta. Set `SMTP_RELAY_HOST=smtp.postmarkapp.com:587`. |
| **SendGrid** | $20/mo for 50k | 30min | Default OAuth-friendly relay; widely supported. Set `SMTP_RELAY_HOST=smtp.sendgrid.net:587`. |

Recommendation for beta: **Postmark** (free tier, fast setup). Switch to SES once volume justifies the operational overhead.

## Why this is "Day-2", not "feature work"

The code that exercises every byte of an outgoing PQC-encrypted email is already covered by:

- `tests/email_transport/test_pqc_envelope.py` — encrypt/decrypt roundtrip, large bodies, tampered ciphertext rejection, JSON-serialisability
- `tests/email_transport/test_smtp_receive.py`, `test_imap_serve.py` — SMTP receive + IMAP serve handlers
- `tests/email_transport/test_dkim_signing.py` — config sanity (7 tests) + header parser (3 tests) + **live OpenDKIM signer** (1 test, verified 2026-05-01)
- `tests/email_transport/test_ttl_header.py` — server-side self-destruct via `X-Zipminator-TTL`
- `tests/email_anonymization/test_attachment_pipeline.py` — no-plaintext-PII invariant through the full envelope
- `tests/mail/test_e2e_pqc_mail.py` — mock transport roundtrip, ciphertext header sizing, multi-message delivery, tampered-bytes rejection
- `tests/mail/test_pqc_mail_config.py` — Postfix `main.cf`, Dovecot SSL, TLS 1.2 minimum, compose service definitions

What integration tests against a live GreenMail container would add: **delivery confirmation that the wire-format messages we already verify in unit tests actually traverse a real SMTP/IMAP stack**. Useful as a deploy-time smoke, not as a code-correctness gate.
